# 0006. 依赖版本基线锁定与升级治理策略

## 状态

Accepted (已接受)

## 背景与决策上下文

作为面向现代企业级中后台与微服务架构的前端基础设施底座（`ateng-ui`），工程面临着“**追新导致下游踩坑**”与“**守旧背负已知缺陷**”的经典矛盾。

在针对最新版本（如 Vue `3.5.44` 与 Element Plus `2.14.7`）的审视中，我们辨析了两种截然不同的升级范式：

- **盲目激进追新 (Bleeding-Edge)**：如在工具链尚不稳定时跨越破坏性 Major 大版本（如 pnpm 10 封杀安装脚本、未稳定的框架 Alpha/Beta 版）。这类变更破坏向下兼容，违背基础设施的稳健基调。
- **成熟体系稳态补丁跟进 (Mature Patch Up-to-date)**：Vue 3.5 早已进入稳定成熟期，`3.5.44` 是历经 44 次迭代后的生产集大成者；Element Plus `2.14.7` 同样是 2.x 系列两年打磨的成果，严格保持向后兼容并修复了数十项核心组件边缘缺陷。

为了从根本上消除版本选型的心智内耗，对齐 `ateng-boot` ADR-0006 治理哲学，特确立长效的依赖版本升级治理策略。

## 架构决策

1. **主干稳态优先，克制破坏性演进 (LTS & Stable Core First)**：
   - 基础包管理器（pnpm 9.x）与核心语言（TypeScript 5.x）优先锁定主流稳定 LTS 分支，严禁在未经架构评估的情况下抢跑破坏性 Major 大版本。
2. **成熟体系补丁版本及时跟进 (Mature Patches Up-to-date)**：
   - 处于当前稳定生命周期分支内的补丁版本（如 Vue 3.5.x、Element Plus 2.14.x、Axios 1.7.x），积极且定期跟进升级，充分汲取社区的 Bug 修复、内存优化与安全防御红利。
3. **基础设施库与自验应用的“双轨依赖隔离”契约 (Dual-Track Decoupling)**：
   - **公共组件/Hooks 库 (`packages/*`) 遵循“宽进”**：在 `peerDependencies` 中声明宽泛的兼容范围（如 `"element-plus": ">=2.8.0"`, `"vue": ">=3.5.0"`），绝不强加给下游存量项目版本升级负担；
   - **自验展厅与测试沙箱 (`apps/*`) 遵循“严出”**：显式锁定当前最新的稳定 Patch（如 `element-plus: ^2.14.7`, `vue: ^3.5.44`），确保在最严苛的生产环境中执行全维度自动化回归验证。
4. **全量测试准出红线 (Quality Gate Redline)**：
   - 任何依赖调整必须以 `pnpm run build && pnpm run test` 100% 绿色通过，并在自验工程中完成端到端交互冒烟作为准出验收标准。

## 效果与权衡

- **收益**：既享受了官方长期迭代的高质量补丁红利，又通过双轨机制彻底解除了对下游业务工程的强制绑定，完美契合企业级工业基础设施套件的初心与定位。
- **代价**：在维护公共包代码时，需始终面向最低兼容标准（2.8.0+）编程，禁止私自使用新小版本中引入的实验性内部 API。
