# 0039. 前端工业级文档规范、三要素就近闭环与 Sample 可视化场景看板架构

## 状态

Accepted (已接受)

## 背景与决策上下文

在 `ateng-ui` 前端基础设施套件的快速迭代与向数十个子包演进的过程中，文档与样例工程（Sample）的工程治理面临以下典型挑战：

1. **类型与配置严重脱节**：文档中通常只展示组件 `<template>` 调用或 Hook 执行，而关键的 Props/Emits 泛型接口、配置项或 CSS 变量却散落在文末附录或深层类型文件中，开发者查阅时必须频繁上下翻找；
2. **生搬硬套单元测试桩**：示例代码充斥着 `test1`、`dummyData`、`foo`、`bar` 等脱离真实业务的测试桩假数据，降低了作为企业级生产参考范式的价值；
3. **能力章节零碎散落**：因特性分批开发，同一组件族或同一领域的能力被切割追加在文档不同角落，缺乏系统化的领域聚合；
4. **Sample 工程缺乏可视化交互**：部分样例工程退化为仅靠单元测试断言或控制台 `console.log` 打印，开发者启动 Vite 后面对空页面或白屏，无法直观体验状态机流转与 UI 交互；
5. **Sample README 冗余膨胀**：部分样例工程的 `README.md` 大段重复抄录子包原理与全景矩阵，维护成本翻倍且职责不清。

为此，全面对标 `ateng-boot` 工业级治理经验，结合 `ateng-ui` 前端技术基线（Vue 3.5、TypeScript、Element Plus、Vite 6）与 L0~L3 四层洋葱拓扑，亟需确立统一的文档与样例工程架构标准。

---

## 架构决策

### 1. 建立专职规约与真理源索引

- 在 `docs/agents/documentation-specification.md` 建立专职的前端工业级文档与样例工程标准；
- 全局 `AGENTS.md`、`modular-extensibility.md` 与 `module-hardening-and-expansion.md` 确立高权引用与代码审查红牌阻断。

### 2. 子包 `README.md` 标准大纲与“三要素就近闭环”铁律

- **标准大纲骨架**：`0. 全景速查矩阵 (100% 覆盖)` ➔ `1. 模块定位与 pnpm 坐标` ➔ `2. 核心架构与设计不变量` ➔ `3~N. <能力领域大章>` ➔ `附录. 完整 TypeScript 接口/Props/CSS 变量清单`；
- **章节“三要素就近闭环”**：每个业务特性章节必须在当前屏幕内同时闭环：
  1. **专属 TypeScript 契约/配置片段**（Props/Emits/Slots 泛型、Hook Options、CSS Design Tokens）；
  2. **面向实战的业务 Vue/TS 示例**（`<script setup lang="ts">` + `<template>` 或 TS 门面，100% 逆向提取自 Sample 真实业务场景）；
  3. **核心机制与生产边界防御说明**（响应性防丢失、生命周期确定性清理、抗竞态丢弃、雪花 Long ID 防截断、样式 `at-` 隔离等）。
- **能力领域大章收敛**：同类功能强制按业务领域或交互组件族聚合为一级大章，杜绝随意追加零散小节；
- **真实业务语义场景驱动**：全面禁止测试桩假数据，必须演化为商品表格、切片上传、抗竞态搜索、长连日志终端等真实高频业务模型。

### 3. Sample 样例工程分层弹性可视化看板与双模架构

- **分层弹性场景看板**：
  - **L0 纯 TS 原生**：保持平台中立与零 UI/零 Vue 依赖，以原生 TS 场景脚本 + 原生 DOM 协议触发器构建请求与大数高亮看板；
  - **L1 无头 / L2 扩展**：按领域在 `src/components/*Scenario.vue` 构建独立场景卡片，单页 Tab 驱动实时监视状态机；
  - **L3 UI 表现层**：在 `src/views/*` 配合 `vue-router` 构建路由级企业展厅；
  - 严禁全量逻辑堆砌在单一 `App.vue` 或仅靠 `console.log` 敷衍。
- **离线 Mock 与真实网关双模机制**：默认依托本地 Mock / MSW 实现 100% 离线自洽，支持通过 `.env.local` 代理直连真实后端网关服务。

### 4. Sample `README.md` 四段式极简体验卡模板

Sample 自身的 `README.md` 彻底剥离全景矩阵与底层原理，严格采用四段式体验卡：

1. **快速启动与服务端口**（固定独立端口 3001~3010 与启动命令）；
2. **运行环境与 Mock 双模切换**（离线自洽 Mock 与 `.env.local` 真实网关）；
3. **核心场景看板与交互路由表**（表格形式呈现：场景分类、组件/路由路径、可视化交互操作与验证重点）；
4. **全真自动化回归命令**（`pnpm --filter ... typecheck && lint && test && build`）。

### 5. “Sample-First” 逆向研发流与六大审查红牌

- 研发严格遵循：`真实业务组件` ➔ `场景看板交互` ➔ `端到端测试全绿` ➔ `逆向提取至子包 README` ➔ `编写 Sample 体验卡`；
- `/code-review` 确立六大一票否决红线（类型/配置脱节、章节散落割裂、测试桩生搬硬套、缺少场景看板或单文件臃肿、Sample 文档膨胀、伪代码凭空脑补）。

---

## 效果与权衡

### 收益 (Benefits)

1. **极致的使用者体验**：查阅文档时，Props/类型、实操代码与底层原理同屏闭环，学习成本大幅降低；
2. **100% 可信的示例代码**：文档代码均 1:1 逆向提取自已验证通过的可视化 Sample，彻底杜绝语法失效与伪代码；
3. **开箱即用的可视化体验**：开发者克隆项目后启动 Vite 即可直接在浏览器中交互自验，加速生态理解；
4. **工程职责清晰**：子包 README 专注真理源与深度原理，Sample README 专注启动与场景导览，消灭内容冗余。

### 代价 (Trade-offs)

- 新增或重构特性时，必须先在 Sample 中构建可视化场景并跑通测试，前置研发闭环步骤增加；但该成本能完全抵消后续文档失效、测试不足带来的巨大维护债务。
